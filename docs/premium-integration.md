# Premium integration contract

The extension-side Premium boundary is provider-neutral. Stripe, Paddle, Lemon Squeezy, or another provider can sit behind the same server contract without changing popup or download code.

## Security boundary

- Never package payment-provider secret keys in the extension.
- The server creates checkout and customer-portal sessions.
- The server consumes billing webhooks and decides the current entitlement.
- The extension stores a random installation ID and a short-lived entitlement cache.
- Every active or trial entitlement must include a future `validUntil`; missing or expired timestamps fail closed to Free.
- The installation ID is a bearer identifier. Do not log it or expose it in UI responses.

## Configuration

Set `apiBaseUrl` in `premium-config.js`:

```js
globalThis.CRAWLCAST_PREMIUM_CONFIG = Object.freeze({
  apiBaseUrl: 'https://api.example.com',
  checkoutPath: '/v1/premium/checkout',
  entitlementPath: '/v1/premium/entitlement',
  portalPath: '/v1/premium/portal',
  cacheTtlMs: 15 * 60 * 1000,
  requestTimeoutMs: 10 * 1000
});
```

The extension sends JSON with:

```json
{
  "installationId": "random UUID generated by the extension",
  "extensionVersion": "0.2.0"
}
```

## Endpoints

All endpoints use `POST` and return JSON.

### Create checkout

`POST /v1/premium/checkout`

```json
{
  "checkoutUrl": "https://payment-provider.example/checkout/session"
}
```

### Resolve entitlement

`POST /v1/premium/entitlement`

Free response:

```json
{
  "tier": "free",
  "status": "free",
  "features": [],
  "validUntil": null
}
```

Active response:

```json
{
  "tier": "premium",
  "status": "active",
  "features": ["unlimited_downloads"],
  "validUntil": "2026-10-20T00:00:00.000Z"
}
```

Supported statuses are `free`, `active`, `trialing`, `past_due`, `canceled`, and `expired`. Only `active` and `trialing` can unlock features.

### Create customer portal

`POST /v1/premium/portal`

```json
{
  "portalUrl": "https://payment-provider.example/customer/session"
}
```

The extension accepts only HTTPS action URLs, except localhost during development.

## Runtime messages

| Message | Purpose |
|---|---|
| `getPremiumState` | Read cached state and refresh it when stale. |
| `refreshPremiumState` | Force an entitlement refresh after checkout or account changes. |
| `startPremiumCheckout` | Request checkout from the server and open it in a browser tab. |
| `openPremiumPortal` | Request a customer-portal session and open it in a browser tab. |

## Current feature gate

`unlimited_downloads` bypasses the one-download-per-hour Free limit. The background service worker enforces this; the popup only reflects the result.

## Development test mode

Set `enablePremiumTestMode: true` in `premium-config.js` to make the header tier indicator clickable. It simulates the same `unlimitedDownloads` feature used by a real Premium entitlement and persists across popup closes. Set the flag to `false` before packaging a production build; the Premium service defaults this flag to disabled and rejects test-toggle requests when it is off.
